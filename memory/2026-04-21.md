## 14:30 CDT — queue_reply.py blank message bug fixed

**Root cause:** When calling `queue_reply.py "Coconut + Molty + Joerg" < /tmp/reply.txt`, the script used `sys.argv[1:]` as the reply text instead of reading stdin. The chat name became the message body.

**Fix:** Refactored queue_reply.py to ONLY read reply body from stdin. Positional args are rejected with an error. Only `--chat-id <id>` flag accepted. This makes the failure mode structurally impossible.

**Why:** Joel flagged blank Teams messages multiple times. Prior "fixes" were behavioral (promise to use stdin) but the code still accepted argv as fallback. The architectural fix removes the footgun entirely.

**Lesson:** When a bug recurs despite behavioral fixes, the code path that enables it must be removed, not just avoided.

## 15:28 CDT — Chat bleed prevention analysis (Joel request)

Joel asked: what problems can occur with chats, how to prevent them, and review Ryan Duff's approach.

### FlyBot's Architecture (from Ryan's Teams message)
- **Persistent webhook subscriptions** — chats in `persistent-monitors.json` with alias, chatId, participate flag
- **Single canonical message path** — all outbound via `teams-msg.mjs`, looks up chatId by alias (never by name), auto-signs `— FlyBot 🪰`, no alternative send paths
- **Read-before-write** — `teams-check.mjs <alias>` reads recent messages AND subscribes webhook before first reply
- **One main session** — heartbeat sessions are read-only, all Teams writes through main session only
- **Unknown chats** — labeled "unknown", reads history before deciding to engage
- **Rule Zero** — acknowledge in-chat before running tools ("On it" → work → result)
- **FlyBot's cracks** (per Ryan): alias lookup only protects if alias exists; concurrent sessions used to cause contradictions (fixed by routing all writes through main); MEMORY.md at 41KB and growing

### Agentic Governance Gateway wiki page (2351071774)
- Ryan's PATCH incident: FlyBot asked to invite 1 person, wrote raw Graph API PATCH that full-replaced attendee list → ~95 cancellation emails
- Three-tier permission model: Allow (auto-execute), Approve Only (human review), Disabled (blocked)

- AI Guard inline on every request (input+output inspection)
