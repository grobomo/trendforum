## Bridge Resilience Improvements (Issue #11)

Joel requested the bridge handle API interruptions more gracefully. Shipped three changes:

### 1. `openclaw_client.py` — Retry + Circuit Breaker
- Transient errors (timeouts, 429, 5xx) retry up to 3x with exponential backoff (5s → 10s → 20s)
- Non-transient errors fail immediately
- Circuit breaker opens after 5 consecutive failures, cools down 60s
- Config-driven: `max_retries`, `base_backoff_seconds`, `request_timeout_seconds`

### 2. `github_channel.py` — Deferred Retry Queue + Dead Letter
- Failed events use time-based deferral (30s → 60s → ... 10min cap) instead of immediate retry
- Retry limit 3 → 5 to survive longer outages
- Dead-lettered events logged in state (last 50 kept) instead of silently dropped
- Also filters out NO_REPLY / HEARTBEAT_OK responses from being posted

### 3. `bridge.py` — Startup Resilience
- Startup connectivity check retries 5x with increasing waits instead of crashing

## Teams Chat — Switched to Cron Poller

The old custom Teams bridge (in github-bridge) was a disaster — it relayed each Teams message individually to OpenClaw as a standalone chat completion, with no conversation context. Result: Coconut replied to every historical message at once ("Coconut Bourne" moment).

### New approach: `scripts/teams-poller/`
- **poll_teams.py** — polls MS Graph for new messages, builds conversation context (last 30 messages), presents new messages with full chat history
- **send_reply.py** — posts replies back to Teams with @mentions and bot signature
- **config.json** — chat_id, bot_signature, context window settings
- State tracked in `~/.openclaw/teams-poller/state.json`
- Skips stale messages (>10 min old) to avoid replaying backlogs after outages
- Uses same msgraph lib at `~/lib/teams-agent`
- Cron job `teams-poll` runs every 1 minute, fires system-event to main session
- Old bridge Teams channel disabled (config.json `teams.enabled: false`)
- First real reply sent successfully to Teams chat

### Key improvements over old bridge
1. Full conversation context (30 messages) instead of isolated message relay
2. Runs as me (main session) so I have memory, personality, context
3. Stale message filtering prevents replay storms
4. Bot signature detection skips own posts
