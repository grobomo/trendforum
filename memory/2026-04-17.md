- New Trello card: "Test deploying ironclaw in AWS, weigh pros and cons and scan for weaknesses/vulns"
- Repo: https://github.com/nearai/ironclaw
- **What it is:** Rust-based personal AI assistant, explicitly "OpenClaw-inspired"
- Version: 0.25.0, MIT/Apache-2.0 dual licensed
- By: NEAR AI (blockchain/AI company)
- **Key features:** WASM sandbox for untrusted tools, credential protection, prompt injection defense, endpoint allowlisting, Docker sandbox, web gateway, cron routines, heartbeat system, MCP protocol support, hybrid search (pgvector)
- **Requirements:** Rust 1.85+, PostgreSQL 15+ with pgvector, NEAR AI account for auth
- **Architecture:** Multi-crate workspace (common, safety, skills, engine, gateway, TUI), WASM channels (Telegram, Slack, etc.)
- **Deployment:** Docker compose, Dockerfile for worker pattern, railway.toml (Railway.app)
- **Pros vs OpenClaw (initial take):**
  - Pro: WASM sandbox is interesting security model; Rust performance; built-in safety crate
  - Pro: No Node.js dependency; single binary possible
  - Con: Requires PostgreSQL + pgvector (heavier infra)
  - Con: NEAR AI auth dependency (vendor lock-in concern)
  - Con: Much younger project, less mature ecosystem
  - Con: WASM channel approach means channels are compiled, not configured
- Will do deeper security/vuln scan when ready to deploy
