## trello-work Timeout Investigation (05:10 CDT)

### Joel's question: "Why didn't metacognition notice the trello-work timeouts?"

**Root cause of timeouts:**
- trello-work had `timeoutSeconds: 900` (15m) with `every: 15m` — zero headroom
- Successful runs avg 400-900s (6-15min). Any complex card = timeout guaranteed
- 5 of last 10 runs timed out (50%)

**Why metacog missed it:**
- No `cron-health` module existed. Metacog monitored comms infra (Teams webhooks, Slack channels, email polling, GitHub bridge) but NOT cron job health itself.
- The pattern detector saw 239x exec errors but those were generic — no specific cron timeout pattern matching.

**Fixes applied:**
1. ✅ `timeoutSeconds: 900 → 1800` (30 min) — room for complex cards
2. ✅ `every: 15m → 30m` — interval matches new timeout, no overlap
3. ✅ Built `cron-health.py` metacog module — monitors consecutive errors, timeout ratios, duration creep, stale jobs, overlap risk
4. ✅ Registered in `metacog.yaml` as `quick` tier
5. ✅ First run: 29 pass, 1 fail (trello-work consecutive errors), 3 warn
6. ✅ Enabled `--failure-alert` on trello-work: alerts after 2 consecutive errors, 1h cooldown

**Automation for next time:**
- cron-health module runs every metacog cycle (1h via orchestrator)
- Detects: consecutive failures, timeout ratio >30%, duration approaching timeout, stale/overlapping runs
- Built-in failure alerting now on the cron job itself
- Both layers: metacog catches patterns, cron alerts catch immediate failures

## Trello Webhook Processing (05:30 CDT)

### Security Incident: Credential Leak in Trello Card
- **What:** Metacog session analyzer found Trello API key in `openclaw-dm/audit.log`, created a Trello card with the actual key in the title
- **Root cause 1:** `sync_to_trello.py` logs full URLs including API key+token in error messages
- **Root cause 2:** `trello-bridge.py` (metacog module) passes raw finding text to card titles without sanitization
- **Actions taken:**
  1. Sanitized Trello card title and description (card 69ede7e7)
  2. Scrubbed `openclaw-dm/audit.log` — masked all key/token values
  3. Sanitized `trello-bridge-state.json`
  4. Fixed `sync_to_trello.py` — added regex masking for credentials in error messages
  5. Fixed `trello-bridge.py` — added `sanitize_credentials()` function applied to all card names/descriptions
  6. Alerted Joel via Slack DM
- **Risk assessment:** Trello board is workspace-private (not public), exposure limited. But defense-in-depth — credentials should never appear in card content.
- **Lesson:** Any system that surfaces log content to external surfaces (Trello, Slack, etc.) needs credential stripping. Metacog is an attack surface for credential leakage.
